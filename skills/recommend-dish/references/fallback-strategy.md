# 推荐兜底链详细说明

当用户对推荐结果不满意，或本地知识库无法满足查询时，按以下 4 层顺序兜底。**前一层失败才进入下一层**，不要直接跳到后面。

## Layer 1: 本地知识库（recommender.py）

正常路径。命令：

```bash
python3 "${CLAUDE_PLUGIN_ROOT}/scripts/recommender.py" --count 3 --keywords "..." --price-tier "..."
```

判定**成功**：`exhausted=false` 且 `dishes` 数量等于 `count`。

判定**进入 Layer 2**：`exhausted=true` 或 `returned < count`。

## Layer 2: 降级过滤后重试

脚本内部已经做了"价格档松弛"。如果 `filters.relaxed=true` 仍然 exhausted，你需要在调用时**主动去掉次要约束**重试。

去除约束的优先级（从最易去到最不易去）：

1. 去 `--price-tier` 和 `--max-price`
2. 去 `--cuisine`
3. 去 `--geo` / `--region`
4. 把 `--keywords` 从 AND-like 改成只保留 1 个最重要的

每次只去掉**一项**，重试，仍 exhausted 再去下一项。

呈现时告知用户："你想要的 [X] 候选不足，已扩大到 [Y]"。

## Layer 3: Web 搜索

Layer 2 完全失败（4 项都去完仍无结果，或用户明确说"网上搜搜"）时进入。

```
调用 WebSearch（或当前 agent 的等价能力）
查询模板：
  "<用户原话> 推荐 菜品"
  或
  "<关键词> 菜 推荐 2026"
```

从搜索结果中筛选：
- 优先大众评价/食谱网站（如美食类博客、评价聚合站）
- 提取菜名 + 一句话简介
- 给出 3 个推荐

**必须标注**：「以下推荐来自网络搜索（来源：xxx），不在本地菜单库内」。

## Layer 4: LLM 常识兜底

仅在以下情况进入：
- Web 搜索失败（无结果 / 无网络）
- Web 搜索结果质量极差（明显广告/无关）
- 用户明确说"不用搜了，你随便推几个"

直接基于通用知识给出推荐。

**必须**：
- 明确告知用户「这些菜品不在本地知识库内，是基于我的通用知识推荐，仅供参考」
- 推荐数量不超过 3 个
- 不编造价格（除非用户问，且明确说"大致价位"）
- 鼓励用户给出更具体偏好，回到 Layer 1

## 何时主动停止兜底

如果用户说：
- 「算了不吃了」「我自己想吧」 → 立刻停止，简短致歉
- 重复说"都不喜欢"3 次以上 → 反问用户具体不满意的点（口味？价位？菜系？），而不是无限推荐

## 反面示例

❌ **错的**：用户说"推荐高档川菜"，本地只有 1 道 → 直接跳到 Web 搜索

   正确做法：先松弛价格档，川菜全部 16 道都可选，再推荐

❌ **错的**：本地推荐返回成功，但你觉得"不够好"，主动追加 Web 搜索

   正确做法：用户没要求时不主动追加；尊重知识库结果

❌ **错的**：兜底到 LLM 常识时不标注来源

   正确做法：必须明确标注「非知识库菜品」，避免用户误以为系统真的有这些菜
