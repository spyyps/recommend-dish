# 美食推荐 Skill

## 用途

帮用户从 462 道菜（覆盖 41 个菜系、10 个地区）中按偏好做加权随机推荐。算法已处理菜系数据不均、关键词复合加权、推荐多样性等问题。

## 触发场景

- 「推荐晚餐 / 早餐 / 午餐 / 宵夜」「推荐一个菜」「有什么好吃的」
- 「不知道吃什么」「来点饭」「随便给我推荐几个菜」
- 「想吃点辣的 / 海鲜 / 牛肉 / 甜的」
- 「便宜点的菜」「想吃高档点的」「请客吃什么好」
- 「换一批」「不喜欢这些，再来几个」（紧接前一次推荐时）

## 工作流（必须按顺序）

### 步骤 1：解析用户意图

从对话中提取以下参数（不传则忽略）：

| 参数 | 来源 | 示例 |
|------|------|------|
| `--count` | 用户明确要的主选数量。默认 1 | "推荐 3 个" → 3 |
| `--alternates` | 备选数量。默认 3（与主选互不重复） | 一般不用传，保持默认 3 即可 |
| `--keywords` | 口味/食材/类型词，逗号分隔 | "想吃辣的牛肉" → `辣,牛肉` |
| `--price-tier` | 价位描述 | "便宜" → `经济`；"便宜实惠" → `实惠`；"中等" → `中档`；"高档/贵的" → `高档`；"极致奢华" → `奢华` |
| `--max-price` | 明确价格上限 | "50 块以内" → 50 |
| `--cuisine` | 菜系名 | "想吃川菜" → `川菜` |
| `--region` | 地区名 | "亚洲菜" → 不填（用 geo）；"中华料理" → 填 region |
| `--geo` | 地理大类 | "亚洲菜" → `亚洲`；"欧洲菜" → `欧洲` |
| `--exclude-ids` | 上一轮已推荐的 ID | "换一批" 时用 |

**推荐模式说明**：默认每次返回 **1 道主选 + 3 道备选**，互不重复。主选是你最该吃的，备选是「不喜欢主选时可换」。只有用户明确说"多推荐几个"时才提高 `--count`。

**支持的关键词（不在此集合的不要传）：**
- 口味：`麻辣`、`辣`、`甜`、`酸`、`咸`、`鲜`
- 食材：`海鲜`、`牛肉`、`羊肉`、`猪肉`、`鸡肉`、`素食`
- 类型：`面食`、`米饭类`、`汤`、`甜品`、`烧烤`、`火锅`、`咖喱`、`汉堡披萨`、`饮品`

**否定关键词规则**：用户说「不要太辣」「不吃猪肉」时，**不要**把否定词翻转后传入。直接不传该关键词即可。如果用户明确说「不能吃 X」并影响主菜选择，应在推荐后口头说明「以下选项均不含 X」。

### 步骤 2：调用推荐脚本

```bash
python3 "${CLAUDE_PLUGIN_ROOT}/scripts/recommender.py" \
  --count <默认1> \
  --alternates <默认3> \
  --keywords "<逗号分隔，可空>" \
  --price-tier "<档位，可空>" \
  --cuisine "<菜系，可空>" \
  --geo "<地理大类，可空>" \
  --exclude-ids "<逗号分隔，可空>"
```

未传的参数省略对应行即可（count/alternates 都有默认值，通常不用写）。脚本会自动在 `${CLAUDE_PLUGIN_ROOT}/knowledge_base` 下读知识库。

### 步骤 3：解析输出

脚本输出单行 JSON：

```json
{
  "main": {"id": "...", "name": "...", "price": 38, "cuisine": "川菜", "description": "..."},
  "alternates": [{"id": "...", "name": "...", ...}, ...],
  "dishes": [...],
  "exhausted": false,
  "filters": {..., "relaxed": true, "relax_note": "..."},
  "candidate_pool_size": 16,
  "returned": 4
}
```

- `main`：主选菜品（1 道，最推荐）
- `alternates`：备选菜品数组（默认 3 道，与主选互不重复）
- `dishes`：向后兼容字段 = `[main, *alternates]`
- 若 `main` 非空：进入步骤 4
- 若 `exhausted=true` 或 `main=null`：进入兜底链（步骤 5）

### 步骤 4：友好呈现给用户

模板（主选突出，备选次之）：

> 给你推荐：**菜名** ¥价格（菜系） — 一句话描述
>
> 备选：
> 1. **菜名** ¥价格（菜系） — 一句话描述
> 2. ...
>
> 不喜欢可以告诉我「换一批」。

附加说明（按需）：
- 若 `filters.relaxed=true`：在推荐后补一句「（原档位 [X] 候选不足，已扩大范围）」
- 若 `returned < count + alternates`：说明「目前知识库里符合的菜不够，先给你这些」
- 备选可省略描述或合并一行展示，避免信息过载

### 步骤 5：兜底链

详细见 `references/fallback-strategy.md`。简版：

1. **自动放宽**（脚本已内置）：候选 < count+alternates 时自动去掉价格档重试一次
2. **降级过滤**：若仍 exhausted，去掉次要约束（先去 price-tier，再去 cuisine）后再调
3. **Web 搜索**：调用 WebSearch 工具，查询如 `"<用户原话> 推荐菜品"`，从结果中挑 3 个推荐
4. **LLM 常识兜底**：基于通用知识推荐 3 道，**必须明确标注「这些不在我们的菜单库内，是基于常识的推荐」**

### 步骤 6：处理「换一批」

用户接着说「换一批」「不喜欢这些」「再来 N 个」时：
1. 把上一轮 `dishes` 的所有 `id`（含主选+备选）加入 `--exclude-ids`
2. 沿用上一轮的其他参数
3. 重新调脚本

跨多轮要持续累积 `exclude-ids`，避免重复推荐。

## 输出格式范例

**正常情况**：

> 给你推荐：**担担面** ¥18（川菜） — 碱水面淋上肉末花生碎和红油，麻辣干香
>
> 备选：
> 1. **泰式冬阴功汤** ¥45（泰国菜） — 酸辣鲜美的海鲜汤
> 2. **意式提拉米苏** ¥48（意大利菜） — 经典咖啡风味甜品
> 3. **咕噜肉** ¥42（粤菜） — 酸甜开胃
>
> 不喜欢可以告诉我「换一批」。

**触发松弛**：

> 给你推荐：**水煮鱼** ¥78（川菜） — 鲜活鱼片在麻辣汤底中烫熟
>
> 备选：
> 1. **辣子鸡** ¥52（川菜） — 鸡块炸至酥脆后与大量干辣椒和花椒同炒
> 2. **担担面** ¥18（川菜） — 碱水面淋上肉末花生碎和红油
>
> （你想要的「高档」川菜候选不足，已扩大到全部价位。）

**触发兜底**：

> 我们的知识库里没有完全符合的菜。让我帮你搜一下网络……
> [调 WebSearch]
> 根据网络搜索，给你推荐：
> 1. ... （来源：xxx.com）
> ...
> ⚠️ 这些菜品不在我们的本地菜单库内，仅供参考。

## 关键约束

- **始终先尝试本地知识库**，不要直接跳到 Web 搜索或 LLM 常识
- **不要凭空编造菜名或价格**——若知识库没有，就走兜底
- **保留 `id`** 在内部用于 exclude-ids 去重，对用户呈现时不显示 ID
- **价格单位是 CNY**，无需向用户重复
